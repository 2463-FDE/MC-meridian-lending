# spec_diff_gate.sh map — one entry per line: <code_path> => <required_spec_or_adr_path>
#
# A line means: if <code_path> exists in this tree, then
# <required_spec_or_adr_path> must also exist. It does NOT require the two be
# touched in the same PR — spec and implementation land in separate PRs/weeks
# here on purpose (see docs/kb.md weekly cadence). This is an existence check,
# not a diff check.
#
# Only list a code area once its paired spec/ADR has actually merged to main.
# Money-moving/decisioning services with no spec merged yet (e.g.
# servicing-service pre-week-6) are deliberately absent — adding them before
# the pairing exists would fail this gate for work already on main.
#
# Add a line here when a week's spec+ADR merges and covers a code path that
# didn't have one yet. Remove a line only if the code path is deleted.
#
# COVERAGE IS AUDITED. Every tracked adr/*.md and docs/spec-*.md must appear
# either on the right-hand side of a line below or in an `# EXEMPT:` line, or
# the gate fails — so a merged spec/ADR with code-path obligations cannot be
# silently left out of the map. Exemption syntax, reason mandatory:
#     # EXEMPT: <doc_path> — <why it has no enforceable code path>
# An EXEMPT entry for a doc that is also mapped, or for a doc that is not a
# tracked file, fails the run: merging or retiring a doc means updating this
# map, not leaving a stale exemption behind.
#
# Prefer the narrowest code path that the doc actually obligates. A directory
# (`services/foo-service/app`) survives deletion of the one file the spec is
# about, so name the file when the obligation is file-specific.

# ADR 0021 is Accepted -- built and merged to main across PRs #68, #76, #79 and
# #80. Three code areas carry its decisions and all three exist on main today:
# assistant.py hosts the framework agent and the five interlocks the loop swap
# moved into the tool closures, chat_model.py is the BaseChatModel wrapper
# that keeps transport, retry, validation and the redaction boundary in

# the lifespan call in main.py that invokes it. The behaviour rung for that is
# the blocking agentic-loop-gate, whose test_agentic_loop.py asserts the boot

# docs/spec-log-aggregation.md is a spec package with no implementation behind
# it yet, mapped rather than exempt on the same footing as weeks 5-8 above:
# several of the code areas it obligates are live today. What this gate can do
# for it is bounded and worth stating, because the previous version of this
# comment claimed more: the check is EXISTENCE-only (see spec_diff_gate.sh's
# header), so it catches DELETION of a mapped path's spec and never catches
# DRIFT in either direction. Drift in the logging copies is redactor-drift's
# and D2's own rung's job, not this one's.
#
# Mapped, one line each, every path live on main today:
#   * the 7 logging_config.py copies (D1, D2) -- per file rather than as
#     services/*/app, the precedent the redactor entries set at the top of this
#     file: a directory-level line survives deletion of the one file the spec
#     is about, and drift comparison alone reads a deleted copy as one fewer
#     copy to check.
#   * docker-compose.yml (D3) -- the gateway log volume the spec adds.
#   * docs/runbook.md (D1(b) rotation arithmetic, D4(d) audit-before-collector
#     ordering). A doc on the left is unusual here and deliberate: the runbook
#     is where two deliverables record their output, so its existence is a real
#     obligation of this spec, not a code area.
#   * every inbound-route surface D5(a) obligates, one line per file. Two
#     kinds of file, both listed, because deleting either one loses the
#     obligation on its own:
#     - each service's app-assembly main.py. Inbound acceptance is registered
#       once for a whole app (a middleware or a shared dependency), not per
#       route, so main.py is the file D5(a)'s "every inbound route" actually
#       obligates: gateway, origination, servicing, kyc, decision, disclosure,
#       payment. gateway's and servicing's main.py already carry ADR 0010 and
#       ADR 0014 lines; two docs for one path is precedented by llm_client.py
#       at the top of this file. origination's line also carries D7(b)'s
#       run-id line.
#     - each router module that declares routes, since a router can be deleted
#       without main.py changing: origination applications.py and offers.py,
#       servicing loans.py, kyc kyc.py, decision decisions.py, disclosure
#       disclosures.py and offers.py, payment payments.py (the router module,
#       not the charge module below).
#   * every outbound seam D5(a) obligates: origination clients.py (the
#     forwarding call sites; it already carries an ADR 0004 line) and
#     payment-service payments.py, the payment->servicing hop that already
#     sends the header. The gateway's own proxy hop lives in its main.py,
#     listed above, so it is not a second line.
#   * the two request_id-handling copies D5(a) names by service rather than by
#     file: decision-service decision.py, which D5(a) names as a minting entry
#     point (its one httpx call goes to the Experian bureau, an external party
#     and not a sibling service, so it is mapped as a minting site and not as
#     an outbound seam), and servicing-service payments.py, which holds a
#     hand-copy of new_request_id while D5(a) lists servicing-service among
#     the services that never mint. Deleting either is a D5 loss this gate
#     should catch. servicing's payments.py already carries an ADR 0014 line;
#     decision.py is new to this map.
#
# Deliberately NOT mapped, and this is not an oversight:
#   * outbound calls to third parties: decision-service's Experian pull and
#     origination-service's Bedrock client under app/llm/. D5(a) obligates
#     forwarding on sibling HTTP clients, and a third party is not a sibling,
#     so those call sites carry no forwarding obligation. decision.py is
#     mapped above, but for its minting, not for that call.
#   * D4's audit/purge script. It does not exist yet, and this gate fails loud
#     on a left-hand path that resolves to nothing -- an unbuilt path is a
#     stale entry, not a placeholder. Add the line in the PR that adds the
#     script.
#   * D7's trace change. app/assistant.py is mapped to ADR 0021 above, which
#     owns the trace surface; D7(a) is deferred pending ADR 0024 (D7(e)), so
#     the obligation is on that ADR, not on this spec, until it lands.
