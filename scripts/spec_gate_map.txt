# spec_diff_gate.sh map — one entry per line: <code_path> => <required_spec_or_adr_path>
#
# A line means: if <code_path> exists in this tree, then
# <required_spec_or_adr_path> must also exist. It does NOT require the two be
# touched in the same PR — spec and implementation land in separate PRs/weeks
# here on purpose (see docs/kb.md weekly cadence). This is an existence check,
# not a diff check.
#
# Only list a code area once its paired spec/ADR has actually merged to main.
# Money-moving/decisioning services with no spec merged yet (e.g.
# servicing-service pre-week-6) are deliberately absent — adding them before
# the pairing exists would fail this gate for work already on main.
#
# Add a line here when a week's spec+ADR merges and covers a code path that
# didn't have one yet. Remove a line only if the code path is deleted.
#
# COVERAGE IS AUDITED. Every tracked adr/*.md and docs/spec-*.md must appear
# either on the right-hand side of a line below or in an `# EXEMPT:` line, or
# the gate fails — so a merged spec/ADR with code-path obligations cannot be
# silently left out of the map. Exemption syntax, reason mandatory:
#     # EXEMPT: <doc_path> — <why it has no enforceable code path>
# An EXEMPT entry for a doc that is also mapped, or for a doc that is not a
# tracked file, fails the run: merging or retiring a doc means updating this
# map, not leaving a stale exemption behind.
#
# Prefer the narrowest code path that the doc actually obligates. A directory
# (`services/foo-service/app`) survives deletion of the one file the spec is
# about, so name the file when the obligation is file-specific.
